### 最低交付条件（每章）

1. 字幕说到的内容，画面里都有对应的东西。
2. 本章核心原理讲清楚了（因果关系能看见）。
3. 与前后章节能衔接（按 `docs/chapter-guide.md` 第 7 节的衔接表）。
4. 关键标注在普通观看尺寸下能看清（1080p 下标题 ≥ 25 px，数值面板正文 ≥ 16 px）。
5. 没有素材加载错误、镜头异常、页面报错（`npm run spot` 结尾没有 ERRORS / FAILED ASSETS）。
6. 能完成截图检查（`npm run spot -- --only NN --every 1 --sheet`）和短片正式导出（`npm run render -- --only NN`）。

## 全局已知问题与待办

- **片尾提到的 `assets/CREDITS.md` 不存在**：需要汇总各章 `credits` 与 `assets/**/manifest.json` 生成完整素材清单（含授权与署名）。`assets/hdri`、`assets/tex`、`assets/models`、`assets/data` 目前没有 manifest。
- **`docs/script.md` 引用的 `docs/style.md` 不存在**：风格总则目前只写在 script.md 开头和 chapter-guide.md 里。
- **字体走 Google Fonts CDN**：导出时需要联网；离线时会回退到系统字体，画面会变，而导出缓存不会察觉。成片前建议把字体放进项目里本地加载。
- **第 05 章的 `fix2d` 绕行代码已经不需要**：现在渲染模式下 `#hud2d` 会正确放大到 1920×1080（第 04 章没用这段代码，draw2d 显示正常）。可在下次改 05 时删掉。
- **模型文件名大小写**：Poly Haven 的 `camera_01`、`chandelier_01`、`schoolchair_01`、`woodenchair_01`、`woodentable_01` 实际文件名首字母大写（如 `WoodenChair_01_1k.gltf`）。macOS 不区分大小写所以能读到，Linux 上会 404。第 02 章的椅子已修；以后用到这几个模型要写准确文件名。
- **没有 GPU 的机器（Linux 软件渲染）导出很慢**：0.5 倍渲染比例下约 2 秒一帧。正式导出建议在有 GPU 的 Mac 上做。

### 性能（第 8 条：先测量，再改结构）

- 目前引擎先构建全部章节再进入播放，还没有全片性能实测数据。用 `npm run perf` 测：首次可播放时间、各章与转场的单帧渲染耗时、贴图 / 几何体数量、暂停时是否仍在渲染、反复跳转后的资源占用。
- 首次测量（04、05 两章，无 GPU 的 Linux 软件渲染，0.5 倍比例，只看相对大小）：
  - 首次可播放：页面打开到两章构建完成约 3 s；全片需在目标机器上重测。
  - **每章第一帧约 10 s**，稳定后 04 约 210 ms / 帧、05 约 38 ms / 帧：启动时的 `renderer.compile` 预编译没有覆盖到第一次真正渲染时的着色器变体（阴影、后期、环境光），着色器仍在播放到该章时才编译——实时播放时表现为进入新章节的卡顿。可以考虑启动时把每个镜头离屏渲染一帧来预热。
  - **暂停时仍在持续渲染**：播放中 0.3 帧/秒、暂停后 0.5 帧/秒（`film.js` 的 `loop` 每帧都 `renderAt`）。暂停时可改成只在跳转 / 窗口变化时渲染。
  - 反复跳转：第一遍跳转会把没画过的镜头首次上传到 GPU（几何体 +231、贴图 +13、着色器 +17）；同样再跳一遍为 +0 / +0 / +0，JS 堆 +0.3 MB——**没有发现资源泄漏**。
- 等全片在目标机器上测完再决定逐章预加载、贴图分档或资源释放；尾声会引用前面各章的镜头，资源释放必须考虑这些依赖（`FILM.chapters[].renders` 已列出）。
